# IATest 开发方案

## 1. 产品与交付模型

IATest 是面向测试开发、研发和业务验收的本地自动化框架。以版本化计划、原生执行、确定性判定和可追溯证据连接 API、Web、桌面、移动、性能、安全、数据与协议测试。CLI、Web 和局域网节点共用应用契约。

方案描述当前实现，不维护按日期追加的开发日志。平台限制、实验通道和未支持项在能力边界中统一说明，不能由模拟测试、发送回执或模型回复推断通过。

## 2. 使用与工作空间

Python 3.11+，配置为 iatest.json，业务资产放在 projects/<project>/。用户可导入接口、管理 Markdown 用例，或创建类型化计划；运行保存独立结果、来源和证据。控制台只绑定回环地址，远程使用需自行提供认证入口。

模型、业务账号、数据库和节点秘密通过已有环境变量引用。配置、开发签名、真实设备标识、测试证书和临时验收资产不作为公开包的业务默认配置。

## 3. 应用架构

CLI/Web → 应用服务 → 领域契约与执行控制 → 原生引擎/远程节点 → 类型化结果 → 报告与知识治理。

| 层 | 当前机制 |
|---|---|
| 交互 | CLI、服务端模板控制台、持久后台任务、取消和多语言 |
| 应用 | 识别、生成、审计、探索、分析、业务资产和版本测试任务 |
| Agent | 角色隔离、注册工具、预算、检查点、模型路由和用量账本 |
| 执行 | 计划校验、超时/请求/动作/查询/证据预算、资源租约和清理 |
| 原生引擎 | HTTP、CDP/WebDriver、AX/UIAutomation/AT-SPI、Android/iOS Runner、数据/协议/性能/安全 |
| 数据 | Markdown、JSON、SQLite、来源摘要、运行证据和可重建记忆 |
| 分布式 | TLS 节点身份、能力允许列表、全局负载分片、资源协调及 fencing |

## 4. API 与测试资产

文档导入支持 OpenAPI、Swagger、Markdown 和 HTML。规划、场景设计、编译及审计分开，候选必须满足可信契约、明确断言及数据依赖。执行支持选择范围、数据集、受约束生成、鉴权、外部夹具、Mock、链路和有限清理。

批量资产接受结构化模板，安装交付核对包名、版本、证书与摘要。Android APK/APKS/AAB 与合法设备 IPA 使用现有平台工具；框架不替用户生成或替换业务签名。

## 5. UI 与目标探索

浏览器使用原生协议，桌面使用系统无障碍，移动使用签名或授权组件。查询是有界证据，缓存和少量候选不能证明唯一。输入之前重新定位，核对身份、可见性、几何及相应命中条件。

目标探索先冻结业务预期，实际观察和执行，固化真实轨迹后独立回放。图像定位显式启用，只发送授权区域，使用前复核像素和平台绑定；稳定计划不逐步调用模型。

GNOME Wayland 完整模式通过系统门户投递输入，以独立单应用组件读取窗口；权限撤销后语义点击、填字和键鼠操作均停止。Safari 常规模式显式采用导航/定位来源检查，不提供严格后台请求拦截。

## 6. 移动、媒体与 HID

Android 使用 ADB、shell 输入组件和原生探针；iOS 使用已签名 Runner，可通过 USB 或独立 TLS 控制/观察。媒体与控制分别认证，H.264 通过浏览器 WebCodecs 或现有 FFmpeg 解码；流量、时长、代次、关键帧和接收器均有预算。

安卓可作为 iPhone 蓝牙键鼠。普通 App、ADB 托管和有限宿主监控是显式生命周期；完整服务重建的蓝牙重启须由用户启用，不重放未知输入。USB gadget 和 BLE digitizer 软件能力与实际触摸/硬件验收分别记录。

## 7. 性能、安全与数据协议

HTTP/事务及协议会话支持有限负载、局域网分片、原始样本汇总和明确门禁。客户端指标保留 CPU、内存、网络、注册 Metal 或估算电量的实际范围，不混成整机 GPU 或实际焦耳。

安全检查只执行声明的范围、规则、身份与验证链；无障碍自动检查与构建绑定人工复核共同决定条款状态。SQLite/PostgreSQL/MySQL 只读访问受 SQL、表、函数、事务和额度约束。WebSocket、MQTT 及 gRPC 有有限消息和未知投递规则。

## 8. 隔离、权限与恢复

访问策略、进程、容器和完整系统隔离是不同能力。浏览器 worker 保留原生状态，通过注册 RPC 接受有界调用。物理手机不具备完整 OS 沙箱；独立 Android VM 由控制器持有生命周期。

节点经 TLS 和本地策略授权；资源协调使用 SQLite 或固定 etcd 集群。多数派不可用时拒绝新租约，未知占用保留至明确对账。恢复以真实进程/设备身份为准，不按旧 PID 或连接状态推断成功。

## 9. 项目知识与模型用量

知识存储包含条目、来源、生命周期、审核、冲突和注入审计。候选与确认规则分开，检索按项目/接口/环境与预算筛选。生成缓存和增量审计绑定完整契约与策略，敏感原始值不进入共享正文。

供应商实际 Token 与本地估算分别记录，缓存/推理用量是子集，不重复计总数。未报告成本不补造；模型输出不能覆盖执行证据或提升权限。

## 10. Web 产品设计

控制台采用企业产品官网式布局：顶部导航、大标题、宽幅留白、工作流示意、真实项目数据及滚动章节。业务页保留高效表单、表格和后台任务。全局导航为概览、测试工作台、设备与环境、测试资产、执行与报告、项目知识、设置；场景按界面交互、服务数据、专项质量与自动化流程组织。UI 默认采用 AI 目标探索，按目标与通过条件驱动真实观察、操作及独立回放；手工编排作为可选创建方式。资产库统一管理 UI、接口、性能、安全及其它测试的目标、计划与参考资料，提供筛选、详情与关联。其它常用配置使用普通表单，完整 JSON 留在高级区域。

页面切换使用浏览器原生同源 View Transition；自然滚动驱动轻量章节和示意图位移。减少动态效果、无脚本和旧浏览器保留可用内容与导航；不截获滚轮、不重放表单、不用视觉示意冒充业务状态。

## 11. 质量与维护约束

每个状态改变之后需要明确业务断言。缺测、观察不完整、目标歧义、预算耗尽和未知派发不能通过。取消只阻止新动作并尝试释放所属资源，不能回滚业务副作用。

开发验证围绕变化运行最小相关回归，再按风险验证真实环境。发布包包含代码、必要原生源码、静态资源、指南和示例；不包含本地凭据、设备数据或临时故障记录。正式发布由版本、打包与远程发布流程独立管理。

## 12. 明确边界

Apple 原始采集异常、Safari 严格拦截和部分高级上下文、iPhone BLE 多指映射、USB 实物硬件、其它桌面/设备/系统版本、物理手机完整隔离及精确硬件计量不以替代实现冒充完成。当前功能及外部条件统一见能力文档。
