# 判定与证据规范

## 运行结束与测试通过

`lifecycle` 描述排队、执行、完成、失败或取消；`verdict` 表示测试判定。后台任务完成不代表测试通过。所有改变业务状态的步骤之后必须有明确断言。

- `passed`：在声明范围内获得完整证据，确定性断言和门禁满足。
- `failed`：实际观察到声明的条件不满足。
- 无法确定、阻塞或未评估：能力缺失、目标歧义、读取不完整、预算耗尽、未知投递或指标缺测。不能折算成通过。

## UI 证据

目标查询返回完整性、匹配数量和有限候选。唯一性不能由截断列表推断；操作前重新查询，检查目标身份、可见性、几何和相应命中条件。缓存、概览、模型坐标与发送回执不是业务结果。

局部视觉只向模型提供授权目标区域。点击前再次核对像素哈希、视口和可用的平台绑定；图像过期即拒绝。图像模型不能修改冻结的业务预期。

## 性能与安全

时延、吞吐、丢弃与错误率分别报告；不平均多个节点的分位数。客户端耗时不能直接证明服务端根因。缺少明确阈值、有效指标或负载达成条件时，不自动给出容量合格结论。

安全规则仅评价显式授权和实际执行的检查。未发现问题不等于全站安全认证；自动无障碍检查也不能替代所有人工条款复核。

## 未知操作与清理

操作回执丢失时，输入可能已发生；停止后续步骤，不重放该写操作。取消会阻止新动作并尝试释放自己持有的资源，不能回滚已经完成的业务副作用。工作流清理需要明确授权并受到独立预算限制。

## 结果和秘密

保存计划、来源、断言、证据摘要及清理结果。敏感字段脱敏，图像和文件按项目政策显式采集。AI 分析与原始事实、假设、建议分开，模型不能改写原始判定。

文档只说明当前契约和可用边界；开发测试轮次、临时设备标识、Token 单次消耗与原始故障输出不进入用户指南。
