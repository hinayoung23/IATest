# 目标探索与证据分析

UI 可只提供验证目的，操作步骤是可选提示。入口是“测试工作台 → 界面与交互 → AI 目标探索”，浏览器、移动 App 和桌面入口也默认采用这一创建流程；已有明确步骤时可切换手工编排。目标用例和固化计划在“测试资产 → UI 测试”中统一管理。也可通过 CLI 使用。探索会实际操作应用，请指定有权测试的范围。

## UI 目标探索

```bash
iatest test explore web \
  '把昵称改为随机 nickname 并保存，刷新后昵称仍等于 nickname，请自行探索步骤' \
  examples/plans/goal-context.json --project demo
iatest test artifacts --kind ui_case --project demo
iatest test run <固化计划ID> --project demo
```

上下文需要 `start_url` / `allowed_origins`（Web），`profile`（Android/iOS 已有设备配置），或 `platform/process_id/app_id`（desktop）。`rules` 是来源 ID 到可信业务规则的映射，`path_hints` 可给入口提示，`required_steps` 声明按顺序必经的原生动作。无需提供完整操作步骤。`token_budget` 默认48000，可显式设置1000–200000；耗尽时保留阻断结果，不自动提高预算。

`data_generation` 复用现有受约束生成器。`input_env` 将变量名映射到已存在的环境变量名，例如 `{"account":"TEST_ACCOUNT","credential":"TEST_PASSWORD"}`；模型只收到变量名，本地执行器绑定实际值。框架不会创建或修改凭据。

流程如下：

1. 根据目的和规则提交检查项，引用来源原文片段；写操作之前冻结，页面实际内容不能成为预期依据。信息不足时保存 blocked 候选和缺失信息。
2. 通过有限区域摘要和定向查询探索路径，目标需先观察，派发前再次校验。未知派发停止探索。
3. 从实际确认的动作及最终检查编译计划，保留刷新、新会话和必经动作。`ui_wait` 可记录保存完成等中间就绪条件，独立回放会保留这些等待，它们不能替代最终业务预期。模型无法补写未经执行的脚本。动态预期变量必须实际输入。
4. 自动独立回放至少两次，使用新会话及新数据命名空间。稳定通过，或同一业务断言稳定失败，才提升为可运行计划；不确定或基础设施错误只保留候选。
5. 同目的、平台及相同上下文再次探索时复用已验证计划，模型调用为零。`--force` 创建新探索资产，不覆盖原始记录。

动作和预期共用 `{"$value":"nickname"}`。需要确保字符串每次不同请配置 `unique: true`；固定枚举和业务常量仍服从生成约束。普通原生计划也可以使用这些变量引用。

`cleanup_plan` 可显式提供 API 清理计划，引用相同变量。探索结束后会执行，固化后作为工作流 always 节点在每次回放后执行，独立预算 15 秒。未配置时不猜测删除接口。清理失败不会提升用例。

默认探索最多 30 次动作、80 次查询、40 个状态、20 轮模型调用、40 次工具调用、累计 48,000 Token。`timeout_seconds` 默认 240，`replay_count` 默认 2（可设 2–3）。主机检查点仅保留冻结目标、近期观察与动作摘要，完整轨迹按需读取。预算不足时保存候选；复验及后续计划运行不调用模型。

移动端复用原生语义查询、有界概览与新鲜定位配方；编辑框空标签不能作为值。Web、桌面和移动端的真实环境与权限按[能力边界](../reference/capabilities.md)准备。探索结果需要独立回放，不将一次成功推定为通用效率。

## 性能 / 安全分析

```bash
iatest test analyze <运行ID> --project demo
iatest test analyze <运行ID> --baseline <历史ID> \
  --observations observations.json --project demo
iatest test artifacts --kind analysis --project demo
```

控制台性能、安全运行卡片有“AI 证据分析”，可附基线 ID 与观测 JSON；独立分析页展示原始事实、AI 解释/假设及建议。

模型无法改写原始判定。每条建议包含优先级、已有证据引用、预期作用和复测方法，不存在的引用会被拒绝。补充日志/指标属于调用方提供的未验证数据，不能授权工具。

基线必须具备来源记录，且请求、负载、数据策略和环境声明相符；否则不计算差值。声明一致也不能证明服务状态等同，单次压测不能证明统计显著的回归。客户端延迟不能直接确定数据库等服务端根因，安全未评估项继续保留。

## 局部视觉与范围

Web 目标探索现支持明确来源的 frame、open Shadow DOM、新页面和有限滚动。ui_outline 返回有限上下文候选，ui_context 显式进入，控件配方携带上下文；动作后继续观察选中的区域。重复语义观察返回可回查的 trace 引用，检查点也去重相同观察，完整原始轨迹保留。

配置的生成模型明确声明 supports_images=true 时，探索才开放 ui_visual_find，每次最多一张局部 PNG、一次视觉模型调用，整个探索最多两次。图像上限为 1024 边长、524288 像素、1 MiB；Agent 审计只存图像摘要/尺寸及证据引用，不保存 base64。返回最多三个候选；只有唯一候选可供探索动作使用。visual_click 使用前重拍区域，核对像素哈希、视口/DPR、节点身份/几何、遮挡及帧龄，之后仍需可信的确定性业务断言。稳定计划只保存图像绑定坐标配方，不依赖跨会话句柄；图像变化即拒绝。

视觉模型的实际输入用量采用供应商报告；图像 Token 在请求前无法通用精确估计，未报告时标为未知，不能用文本估算冒充图像成本。Web、Android/iOS 均接入局部视觉；移动锚点另绑定屏幕旋转，使用前由原生目标重查和截图复核，不能承诺 Web 式逐点遮挡证明。Android/iOS 可在明确提供 bridge_artifact_id 时读取开发构建的就绪/控件标识提示；它不是业务断言依据，仍必须查询真实 UI。来源片段校验不能形式化证明任意自然语言目的；复杂前置条件需明确提供。详见 [移动高级能力](mobile-advanced.md)。


桌面局部视觉使用相同工具入口，并绑定原生窗口身份。真实图像模型的计划仍需要原生点击和独立业务读回；复验脚本参见[桌面测试](desktop-testing.md)。
