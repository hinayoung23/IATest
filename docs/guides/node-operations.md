# 节点证书与身份轮换

节点控制器使用配置的 TLS 证书和私钥，节点使用明确的 CA 文件及已有令牌环境变量。下面的轮换流程已经用临时 CA、真实 TLS 握手及本地节点执行验证；不修改系统时间、生产证书或真实用户凭据。

## TLS 证书

- 同一 CA 续签：部署新证书及匹配的私钥，受控重启控制器并沿用其数据库和地址。现有节点在建立新连接时验证新证书。当前没有热加载证书接口，不把覆盖磁盘文件视为已完成轮换。
- CA 切换：先向节点部署包含旧、新 CA 的重叠信任文件，并重启相应节点以重建 SSLContext；再切换控制器证书。确认节点能使用新链后，用只包含新 CA 的文件重建客户端。旧 CA 客户端拒绝新链，移除旧 CA 后的新客户端也拒绝旧链。
- 证书过期：握手失败，不关闭证书验证。CA 退役不等于已实现 OCSP 或 CRL 服务。

节点客户端使用标准库 SSLContext 加载 CA，并保留主机名和有效期验证，不依赖 HTTPX 已弃用的字符串 `verify` 参数。

## 身份撤销与恢复

控制器每次认证读取节点配置引用的环境变量；节点进程在启动时载入凭据。凭据变更后，仍持有旧令牌的节点被拒绝，重新启动的节点使用新令牌。实际部署需要按所在服务管理器更新控制器、节点的环境并重启；框架不会读取或改写用户的密钥管理系统。

在途任务不能因重新认证而重新执行。节点心跳持续被拒绝，超过其配置的 1–30 秒租约后取消负载；失联任务及资源状态继续按既有不确定性和 fencing 规则处理。恢复认证后，节点账本拒绝重放已有派发记录。新节点实例注册会把旧实例未完成的任务标为错误；实际外部副作用仍需核对后再显式协调。

```sh
pytest -q tests/test_node_tls_lifecycle.py
pytest -q tests/test_nodes.py -k revoked_node_identity
```

第一项验证真实 TLS 的续签、过期拒绝、CA 重叠与退役及错误身份拒绝；第二项验证实际负载因凭据撤销而停止，恢复认证后请求数不再增加。结论限已测试的服务路径，不等于物理磁盘故障、生产密钥运维或跨机房容灾验收。
