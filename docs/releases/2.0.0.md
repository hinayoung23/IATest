# IATest 2.0.0

PyPI distribution: `iatest-framework==2.0.0` · CLI: `iatest` · Python: 3.11+

## Unified test automation

IATest now brings API, browser, desktop, Android/iOS, performance, security, accessibility, data and protocol testing into typed plans and business workflows. Capabilities include native UI tools, bounded goal exploration, independent replay, explicit rule checks, client measurements, authorized execution nodes and release suites. Platform-specific requirements remain explicit in the capability matrix.

## Goal-first console and assets

UI creation starts with the target, business goal and trusted expected outcome. AI exploration and independent replay lead to goal cases and reusable plans; manual composition is an explicit alternative. The asset library includes UI, API, performance, security, data/protocol, accessibility and workflow assets, with filtering, readable details and links between cases and plans.

The console uses an editorial layout, native page transitions, responsive navigation and reduced-motion support. Devices, assets, execution reports, project knowledge and settings have their own workspaces. Device discovery retains partial results and provides actionable platform diagnostics.

## Naming and migration

This major release changes the Python import namespace:

```python
# 1.x
from ai_apitest.core.config import init_project

# 2.x
from iatest.core.config import init_project
```

Change `python -m ai_apitest` to `python -m iatest`. Update custom fixture/provider module references and automation that imports implementation modules. The install name `iatest-framework`, command `iatest`, project configuration filename and plan contract version remain unchanged.

| Previous location | 2.0 location |
|---|---|
| `ai_apitest/` | `iatest/` |
| `web/templates/dashboard.html` | `web/templates/overview.html` |
| `interfaces.html`, `cases.html`, `reports.html` | `api_contracts.html`, `api_cases.html`, `api_reports.html` |
| `context.html`, `config.html`, `llm_role.html` | `project_knowledge.html`, `settings.html`, `model_role.html` |
| `examples/testing/` | `examples/plans/` |
| Mobile profile examples | `examples/devices/` |
| Mobile execution examples | `examples/plans/` |
| Measurement and HID examples | `examples/measurements/`, `examples/hid/` |
| `examples/test_lab.py`, `goal_lab.py` | `examples/automation_lab.py`, `ui_goal_lab.py` |
| `docs/guides/multi-type-testing.md` | `docs/guides/test-plans.md` |

Use the documentation index to find current example paths. Existing console URLs remain available. The source tree and release distributions exclude local acceptance data, device identities, credentials and generated build products.

## Platform boundaries

Safari advanced interception, Apple raw collector failures, experimental iPhone digitizer mapping, physical USB HID acceptance and precise hardware-level measurements are not generalized into guarantees. Missing evidence remains unassessed or inconclusive. See [capabilities](../reference/capabilities.md), [environment](../reference/environment.md) and [verdict rules](../reference/quality.md).
