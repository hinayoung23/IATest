# IATest 2.0.1

PyPI distribution: `iatest-framework==2.0.1` · CLI: `iatest` · Python: 3.11+

## Project-independent API contracts

Removed an application-specific adapter that had been included in the default document and case-compilation paths. The framework no longer inserts that application's routes, response strings, lifetime defaults or email domain into another project's contract. Console and model examples use generic project names and scenarios.

Business chains preserve explicit `trigger.chain_steps`. A lifecycle rule without declared steps stays available for semantic design; it no longer acquires a built-in route sequence. Dependency proposals require matching fields in documented successful responses. Global Markdown rules attach to an operation only when their evidence explicitly identifies its method and path; unscoped evidence is retained in `global_rule_candidates`.

Chain titles use the current operation summaries instead of labeling every creation or deletion as an email operation. Email constraints still work when their domain, length or template is provided by the current source document.

The trusted-contract compiler version has changed. Reimport documents and regenerate affected API cases to rebuild their contracts; existing user assets are not deleted or silently rewritten. Python imports and plan schemas remain compatible with 2.0.0.

## Release checks

Added contract isolation regressions covering unrelated operations, custom domains and lengths, explicit chains, global rule scope and dependency evidence. CI runs these checks before the complete regression suite. Clean-install acceptance also scans the installed runtime for the removed debug-project binding, so source-tree checks alone cannot certify a distribution.

Upgrade with:

```sh
python -m pip install --upgrade "iatest-framework==2.0.1"
```
