# IATest 2.1.1

PyPI distribution: `iatest-framework==2.1.1` · CLI: `iatest` · Python: 3.11+

## 安全与配置

- 控制台校验所有请求的 Host 与监听端口；写操作始终验证 token 与明确许可的 Origin。默认通过一次性启动链接建立私有会话，页面、任务列表、报告和二进制证据均受保护。取消通道保持独立于长任务锁。
- 模型连接的精确 origin 与凭据引用在本机登记，登记文件独立于普通角色设置；控制台不能把任意进程环境变量改发给未知目标。本机 HTTP 与显式登记的企业代理继续支持。
- 主配置增加 schema、类型、范围和跨字段校验，保留已知旧配置入口。工作空间锁和变更基线保护跨项目更新：不冲突的编辑合并，同字段冲突要求刷新。
- `.env` 不覆盖外部环境和关键运行设置；凭据、输入、数据库及 worker 解析按工作空间读取。新写入和更新的秘密文件采用私有权限，支持 POSIX 与 Windows ACL。
- 调试开关按布尔值解析，默认只记元数据；显式内容诊断脱敏、截断并写入受限轮转日志。Mock LAN 监听需要显式开启，管理历史和重置接口独立保护，敏感 query/body 脱敏。

## 判定、AI 状态与证据

Web/桌面使用明确的检查完成数汇总判定，保留原有“必须有后置断言”校验。空计划不会被放行，正常成功计划仍通过；数据、安全和客户端性能补充检查计数。CLI 只接受 completed+passed。

AI 分析返回独立的结构化状态，兼容文本 API 保留；正式报告元数据包含 AI 分析状态与审计标识。修正 JSON 修复失败时伪称“已使用本地规则”的文案，保留真实异常原因。知识版本读取失败会禁用生成缓存，防止用默认版本复用或写入陈旧内容。有效的知识迁移、工具参数错误拦截和工具权限校验继续保留。

全文索引提供 `context check-index [--repair]`，检查等行数内容漂移和索引结构。`test prune-results` 预览旧运行与证据，`--apply` 才执行清理；被固化资产引用的运行保留。

## 工程与运行优化

请求、任务、引擎、Agent 和模型调用关联 trace/span 标识，错误结构化脱敏，审计记录共享任务预算。新项目默认启用任务预算，旧项目保留预算选择。后台队列改为事件唤醒并保留恢复轮询。

将请求安全、表单凭据、配置 schema、诊断、判定汇总拆成独立模块，CDP/WebDriver 复用有界 frame 等待逻辑，保留后端能力差异。避免不必要的全引擎重写和会话继承体系改造。

Chromium 启动等待端口文件内容完整，避免“文件已创建但尚未写入”导致启动提前失败；等待仍受取消和超时约束。真实浏览器回归消除 favicon 请求排序假设，并使用确定的视觉测试图形，保持视觉锚点变化时拒绝点击的规则。

CI 增加 lint、关键模块类型和分支覆盖率门禁；发布环境通过 lock 与 hash 安装，Actions 固定提交。构建后验证 wheel/sdist 元数据和独立基础安装；新增计划校验、100/1000 个资产读取的 p50/p95 基准及同环境回归比较。库安装者仍可按公开依赖兼容范围选择自己的环境。

## 升级

停止旧进程后升级：

```sh
python -m pip install --upgrade "iatest-framework==2.1.1"
```

资产布局沿用 2.1.0，不要求删除索引或重新导出资产。配置错误现在会在加载/保存时报告明确路径，需修正错误类型和拼写；不能继续依赖非法配置被静默忽略。

启动控制台时使用终端输出的新授权链接，不再假定裸地址可直接访问。首次启动登记已有本地模型引用；新增连接使用 `iatest llm-trust`。反向代理部署显式配置 `web.allowed_origins`。保存新 Key 时选择明确凭据模式，并将角色管理的变量引用登记到目标服务。完整说明见[控制台与凭据](../guides/console-security.md)。

旧项目保留原有任务预算开关；新项目默认开启。原有未知投递停止、独立回放、模型不得改判、原始事实与解释分离等约束保持。浏览器/桌面/移动/HID/远程部署仍按[平台矩阵](../reference/capabilities.md)单独验收；跳过不代表硬件通过。无模型路径见[API、数据与浏览器示例](../guides/deterministic-ci.md)。
